【论文阅读】【USENIX 26'】“别给用户说”：检测与理解恶意Agent技能

发表于2026-10-07|更新于2026-10-07|博文
|浏览量:

论文信息

  • 标题：“Do Not Mention This to the User”: Detecting and Understanding Malicious Agent Skills in the Wild
  • 链接：preprint

解决问题

给Agent装上skills，就能让它们帮人做很多具体的事，可以读文档、写材料等。但隐藏在skill里的一些意图可以被隐藏起来，甚至让使用者都察觉不到。本论文首先提出了这个概念，并收集出一个有意义有标注的数据集。具体来说，论文聚焦于以下问题：

  • 缺乏标注基准：Agent 技能生态（Claude Code、Codex CLI 等）已快速膨胀至 98,380 + 个技能，但此前没有任何经过行为确认的恶意技能标注数据集，防御者无法评估检测工具效果。
  • 静态分析不可靠：现有工具仅靠正则匹配标记 26.1% 的技能为 “可疑”，但无法区分开发者失误与真正的恶意行为，精确率极低。
  • 威胁全貌未知：不清楚恶意技能的攻击规模、技术分布、攻击者策略以及规避检测的手段。

采取方法

三阶段研究方式。

模块 核心做法
数据收集 爬取 skills.rest 和skillsmp.com两大公共仓库，共 98,380 个技能（截至2026 年 1 月）
静态候选识别 设计 14 个检测模式，映射到 MITRE ATT&CK 的 6 个杀伤链阶段：• 代码层（10 个）：正则匹配 Python/Shell/JS 脚本，检测凭据窃取、远程执行、混淆编码等• 指令层（4 个）：用 GPT-5.2 分析 SKILL.md 文档，检测指令覆盖、隐藏指令、行为操纵等筛出 4,287 个候选（4.4%）
动态行为验证 将候选技能放入 Docker 沙箱（2GB 内存、60 秒超时、无网络白名单），通过 tcpdump/auditd/strace 监控实际执行行为，验证是否真的外发数据、连接可疑域名等筛出 762 个候选（0.78%）
人工标注 两位安全专家独立审核，从 4 个维度判定：行为日志、代码审查、文档与行为对比、二元分类最终确认157 个恶意技能，标注632 个漏洞实例（13 种模式）
攻击链分析 构建 13×13 漏洞模式共现矩阵，用 Fisher 精确检验和 Spearman 相关识别攻击链；按复杂度分 3 级（Basic/Intermediate/Advanced）

实验

数据集与pipeline性能

  • 首个大规模标注数据集：157 个行为确认的恶意技能 + 632 个漏洞实例，全部公开可用
  • 管线精确率 99.6%（0.6 个误报），相比现有静态分析工具（Skill Scanner 仅约 1.1% 精确率）提升90 倍以上
  • 仅 10% 未确认样本的抽检就发现 93.2% 是休眠触发器（时间 / 环境触发的延迟恶意），说明确认集是保守下界

攻击发现

  • 单个工业级发布者 smp_170 贡献了 54.1% 的恶意技能（85 个），高度集中化的模板化攻击
  • 两种截然不同的攻击原型：
    • Data Thieves（66%）：以远程脚本执行 (SC2) 为核心，集中做凭据窃取 + 数据外发，OR=22.3
    • Agent Hijackers（10.2%）：以指令覆盖 (P1) 为核心，操纵 LLM 自身决策，绕过安全防护
  • 规避随复杂度单调上升：影子特征（文档中未声明的隐藏功能）从 Level 1 的 0% → Level 2 的 86.1% → Level 3 的 100%
  • 84.2% 的漏洞嵌入在 SKILL.md 自然语言文档中（仅 8.5% 在可执行代码里），传统代码扫描完全失效

生态影响

  • 负责任披露后 157/157（100%）恶意技能已被仓库维护者全部移除，证明标注的准确性和实用性
  • 攻击链覆盖中位数达 3 个阶段，68.2% 的恶意技能横跨≥3 个杀伤链阶段，攻击复杂度已接近成熟的浏览器扩展 / 安卓恶意软件水平
