【论文阅读】【ACSAC 26'】A2ABreak： 对 A2A 协议的系统性安全分析

发表于2026-10-26|更新于2026-10-26|博文
|浏览量:

论文信息

  • 标题：A2ABreak: Systematic Security Analysis of the A2A Protocol

  • 会议：42nd IEEE Annual Computer Security Applications Conference（ACSAC, CCF B）

  • 链接：预印|工作

解决问题

背景：A2A 由 Google 于 2025 年 4 月提出，2025 年 6 月移交 Linux Foundation，数月内获 50+ 厂商（Salesforce、SAP、ServiceNow、MongoDB、LangChain 等）支持，正成为多智能体生态的“水平通信层”——MCP 管 agent 与工具之间的垂直关系，A2A 管 agent 与 agent 之间的水平关系。

为什么危险：

  1. 不透明执行（opaque execution）是 A2A 的核心设计原则：委派方看不到远端 agent 的内部推理、工具调用和中间状态。这保护了知识产权，也意味着委派方无法验证对方拿自己的数据、凭证和产物做了什么。
  2. 安全要求“软”：大量关键控制写成 SHOULD / MAY，连“发现阶段验证 agent 身份”的唯一原语（Agent Card 的 JWS 签名）都是可选的。
  3. 对等方自治且不可信：与 MCP 服务器（完全受宿主控制）不同，A2A 的远端 agent 是“黑盒对等体”，信任模型根本不同，攻击面显著更大。

研究空白：已有工作要么是描述性综述，要么是高层安全架构建议，没有落到规范的状态机上；有针对 token 生命周期的隐私分析，但没有覆盖结构性漏洞；A2A 没有开源参考实现，静态分析、模糊测试、符号执行等实现级手段统统用不上；直接让 LLM 零样本读规范找漏洞也不可靠——作者实测 Claude Opus 4.6 两轮共给出 9 个候选攻击，经对抗验证全部被否。

三个技术挑战：C1 自然语言规范没有形式语义，一句话可能同时含前置条件、规范性要求和数据类型约束；C2 LLM 开放式生成没有“参考答案”，错误会无声流向下游，而人工建模太贵（此前蜂窝协议工作约需 2800 人时）；C3 分析必须可靠（sound）——每条结论都要真的对应规范中的缺失。

核心洞察：A2A 的漏洞不在“它写了什么”，而在“它没写什么”。因此分析放在全合规假设下：所有 MUST/SHOULD/MAY 都被满足、实现无缺陷、传输层安全已建立——此时还能成立的攻击，必然是协议设计本身的缺陷。

A2ABreak

图 2 把 A2ABreak 画成一条“两遍抽取—分层建图—对抗验证”的流水线，并在关键节点标出人工闸门：左半部分是 Stage A，同一份规范被送进两条互不干扰的通道（A1 只抽结构、A2 只抽 RFC 2119 行为规则），A3 对账去重、A4 逐条回查原文，输出 929 条带稳定 ID 的语句；中间是 Stage B，语句先按六个协议阶段切分（B1），每个阶段独立合成一张阶段 FSM（B2），再补上跨阶段迁移（B3），最后装配成统一图并经过确定性去重 D1 与 LLM 语义去重 D2，收敛到 37 状态、76 迁移；右半部分是 Stage C，先在统一 FSM 上做多轮生成式发现（C1），再把每个候选送进“落地—可执行—无规范阻止—原语确实缺失”四步对抗验证与人工复核（C2）。图中 A4、B2/B4、C2 之后的三个检查点，正是这套方法敢于声称“可靠”的结构性原因。

三阶段流水线，阶段之间设强制人工检查点。

Stage A：规范形式化（自然语言 → 可机读语句）

  • A1 结构抽取：抽 FSM 状态、全局约束（CONSTRAINT）、以及定义表/流程图里隐含的迁移；
  • A2 行为抽取：独立地只处理带 RFC 2119 关键词（MUST/SHOULD/MAY）的句子，编码成行为迁移并保留规范性强弱；
  • 设计要点（S1 双通道语义分离）：“结构定义”与“行为规则”在原文中交织，单通道抽取会把类型定义误读成状态迁移；两遍独立抽取再对账，避免语义串味；
  • A3 对账：合并、去重、标记歧义并强制人工复核；
  • A4 规范校验：逐条回查原文，检测幻觉状态、错配的规范性关键词、原文中不存在的守卫条件。
  • 结果：929 条经校验的形式化语句。

Stage B：FSM 构建（语句 → 统一状态机）

  • B1 过滤：不含迁移结构的语句（字段存在性、OneOf 约束）直接剔除——929 条中只有 283 条（30%）进入建模；
  • B2 分阶段合成：对 Discovery / Authentication / Initiation / Task Execution / Interruption / Termination 六个阶段各自合成 FSM，给每个状态标注 actor（client / server / shared / unknown），shared 状态即信任边界；
  • B3 跨阶段迁移解析：连接各阶段出口与下游入口，包括“任务执行 ↔ 中断”的双向环；
  • B4 统一装配 + 两级去重：D1 做命名归一、跨阶段重复状态合并、结构性校验（确定性流程）；D2 由 LLM 处理元状态、直通状态、孤儿状态，并补回被遮蔽的迁移。
  • 结果：37 个状态、76 条迁移；相对原始合成图（38 状态 / 245 迁移）迁移数减少 69%，相对 929 条语句端到端压缩 92%。

Stage C：安全分析（FSM → 漏洞）

  • C1 发现：找四类结构特征——敏感迁移缺少授权守卫、阶段边界缺少检查、可绕过必要前驱直接到达的状态、事件字母表缺口（允许规范未预见的消息序列）。候选须满足：攻击轨迹完全在 A2A 协议内可执行；经规范全文检索确认该原语“确实不存在”（“含糊地甩给实现”不算有意排除）。C1 多轮运行以提升召回；
  • C2 对抗 + 人工验证（四步）：把轨迹落到 FSM 合法状态上 → 在全合规下逐步执行确认可利用 → 确认没有规范性条款能阻止 → 确认缺失的原语确实未被别处定义；最后领域专家独立复核。失败者降级为“不确定”或丢弃，并记录理由。

约束语言（S3）：所有 prompt 嵌入领域特定约束（迁移写成 s1 --c/a--> s2，守卫用 & | ! 与点号属性），强制模型输出机器可验证的形式化表示而非自由文本。

三个代表性攻击：

  • 跨客户端上下文注入：contextId 没有创建者字段、没有访问令牌，任何已认证客户端只要知道 X 就能 SendMessage(taskId=∅, contextId=X)，把自己的任务塞进别人的会话，既读到对方累积的上下文，又把恶意消息写进对方历史；
  • 多跳身份丢失：身份只在传输层建立、不跨跳传播，中间 agent 转发任务时用户身份就丢了；下游返回 TASK_STATE_AUTH_REQUIRED 时，凭证提供方看不到原始主体和委派链，恶意中间人可静默截留、重放凭证；
  • 未认证技能声明：AgentSkill 全是自述字符串，JWS 只证明“卡片是谁发的”，不证明“技能是真的”，恶意 agent 可完全合规地接单、外泄数据、返回伪造产物。

结论：A2A 把上下文所有权、委派来源、能力认证、凭证作用域等关键安全属性当作“实现问题”而非协议不变量，导致缺口直接变成任何合规部署都可被利用的漏洞。未来工作包括 A2A 仿真测试框架、A2A × MCP 组合攻击面、向后兼容的协议级缓解。
