附：places.sqlite 是什么

一句话：它是 Firefox 的“历史 + 书签 + 输入历史”数据库，格式是标准 SQLite 3，文件名固定叫 places.sqlite。

Firefox 把所有 URL 相关的浏览痕迹都写在这里，不在注册表里，也不在 IE 的 WebCache 里——这也是为什么 iehistory 查不到、而它能查到。

主要表结构（Firefox 95 这张库里的）

表 存什么
moz_places 每个 URL 一条：url、title、visit_count、hidden、typed、frecency、last_visit_date
moz_historyvisits 每次访问一条：place_id、visit_date、visit_type、from_visit
moz_bookmarks 书签
moz_inputhistory 地址栏/搜索框里实际敲进去的字符串（自动补全用）
moz_annos / moz_items_annos 注解（下载来源等）
moz_origins / moz_meta 站点聚合信息、库元数据

几个字段的含义要记住：

  • last_visit_date / visit_date：Unix 纪元起的微秒数（PRTime），UTC。除以 1e6 再 datetime(..., 'unixepoch')。
  • typed = 1：这个 URL 是用户手动敲进地址栏的，不是点链接进去的。
  • visit_type：1=LINK 点击、2=TYPED 手输、3=BOOKMARK 书签、4=EMBED 嵌入、5/6=重定向、7=DOWNLOAD、8=FRAMED、9=RELOAD。
  • rev_host：反转的域名（gro.allizom.troppus. = support.mozilla.org.），只用于排序，别被它迷惑。

为什么它会在内存镜像里

Firefox 运行时会打开 places.sqlite，SQLite 通过 mmap/页缓存把它映射进内存，同时 NTFS 文件缓存也会保留这些页。dumpfiles 就是顺着 FILE_OBJECT → DataSection 把这些页重新拼成文件，所以即使磁盘不在手上，也能拿到一份（可能不完整）的数据库。

换成 Chrome / IE 该去哪找（对照）

浏览器 历史数据库 位置 备注
Firefox places.sqlite %APPDATA%\Mozilla\Firefox\Profiles\<随机>.default-release\ 本文这套
Chrome History %LOCALAPPDATA%\Google\Chrome\User Data\Default\History SQLite，表 urls/visits，时间是从 1601 起的微秒
IE WebCacheV01.dat %LOCALAPPDATA%\Microsoft\Windows\WebCache\ ESE 数据库，Vol2 的 iehistory 就是读它
