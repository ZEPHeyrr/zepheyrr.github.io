发表于2026-10-26|更新于2026-10-26|博文
|浏览量:

论文信息

  • 标题：Prεεmpt: Sanitizing Sensitive Prompts for LLMs

  • 会议：NDSS 2026（网络与分布式系统安全年会，美国圣地亚哥；论文编号 s1277）

  • 链接

解决问题

问题：用户把 prompt 发给第三方 LLM API 时，其中的敏感信息（姓名、SSN、信用卡号、年龄、薪资、账户余额……）会完整暴露给模型运营方。作者把威胁主体明确为“模型所有者”，而非训练数据时代的任意 API 使用者。

动机链条：

  1. 隐私风险从训练期迁移到推理期。上下文学习（ICL）让用户把真实样本直接塞进 prompt，DP-SGD 之类的训练期保护对此完全无效。
  2. 现实压力。意大利曾对某聊天机器人发出禁令；三星、亚马逊、苹果等企业限制员工使用公有 LLM；用户普遍缺乏隐私意识，常在不知情中泄露 PII。
  3. 现有方案都不合用：同态加密/安全多方计算安全性好，但对 BERT 做一次推理就要 16 分钟以上；直接删除（redaction）隐私满分、实用性归零；查表替换需要随 prompt 数量线性增长的映射表，有状态、难扩展、易泄露；LLM 改写（如 Papillon）没有形式化保证且实测有大量残留泄露；文本加噪类 DP 方法噪声随文本长度增长（维数灾难），还常破坏 token 的类型/格式。
  4. 缺失的原语：领域里没有一个“既形式化可证、又能保持模型可用”的 prompt 变换定义。

三条设计目标：形式化隐私保证、高可用性（回答接近原始 prompt）、无状态（只存密钥，不存会话状态，从而满足 GDPR/CCPA 的删除权）。

范围界定：只处理“敏感信息可由单个 token 本身推断”的情形；整段上下文的语义敏感性（例如暗示心理疾病的描述）明确留作未来工作。

Prεεmpt

最左侧是用户的一次性注册，配置管理器在此生成并保管用户密钥 K_U、隐私预算 ε 以及每类敏感字段的取值域/格式；中间的 Sanitizer 先用 NER 完成类型标注，把 token 分成 Category I 与 Category II，分别送往 FPE 与 mLDP 两个分支，再由后处理器按辅助串 Ψ 修正 token 间的函数依赖，拼成脱敏后的 prompt；右侧是不可信的 LLM API，全程只见到密文/加噪后的值；返回的响应经 Desanitizer 用同一把密钥把 Category I 的密文精确解回明文，Category II 保持加噪值。整张图刻意不画任何数据库或会话存储，强调“密钥即全部状态”的无状态设计

形式化：把“消毒”定义成密码学对象

prompt sanitizer 定义为四元组 PS = ⟨Setup, Type Annotator, Sanitization, Desanitization⟩：

  • Setup 生成密钥 K；
  • Type Annotator 把 prompt 标注成带类型的 token 序列（如 (50, [Age])），要求 type-preserving——脱敏前后类型序列必须一致（这条直接排除了“把数字改成乱码”的做法）；
  • Sanitization 输出按 token 计等长的脱敏 prompt；
  • Desanitization 用同一密钥还原模型回答。

隐私用博弈刻画：对手提交两个“结构相同”的 prompt，只能看到其中一个的脱敏结果，要猜是哪一个；“结构相同”由泄露函数 L 定义（例如允许泄露 token 长度），优势 Adv = 2·Pr[win] − 1，与保序加密的 IND-FA-OCPA 定义同构。可用性用 quality oracle Q 定义成 (α, β)-utility。

定理 2：Cat-II token 的优势满足 Adv ≤ e^{lε} + negl(λ)（l 为两值最大差，λ 为 FPE 安全参数）。定理 3 把 NER 漏检率吸收进泄露函数。定理 4：对“不变式 prompt”（回答不依赖敏感值本身），达到 (α, α)-utility，即理论零损失。

两类 token，两种工具

类别 判定标准 例子 采用手段
Category I 回答只依赖 token 的格式 姓名、SSN、信用卡号、税号、护照号、银行账号、驾照号、电话、IP 保格式加密 FPE（16 位卡号加密后仍是 16 位数字）
Category II 回答依赖具体数值并参与计算 年龄、薪资、余额、医疗数值 度量本地差分隐私 mLDP（ε/t-mLDP，基于指数机制的 ℓ1 版本）

mLDP 是关键：它保证“越接近的值越可能被映射到一起”，加噪后仍保留大小/序关系，模型做数值比较、加减、阈值判断时依然可算；同时给出“距离越远越难区分”的隐私语义。普通 LDP 会把 5 万改成 300 万，实用性直接崩塌。

三个工程细节

  1. 预算分配：总预算 ε 平均分给所有 Cat-II token（组合定理保证总损失 ≤ ε），防止同一敏感值重复出现被相关性攻击利用。
  2. 辅助串 Ψ：编码 token 间函数依赖（“年薪 = 12 × 月薪”“BMI = 体重/身高²”）。只对 DAG 根节点加噪，其余由依赖推导；因 mLDP 对后处理免疫，推导不额外耗预算。例：年龄 25、出生于 2000 只需对年龄加一次噪，出生年份由后处理算出，重复出现的年龄直接复用。
  3. 无状态：Cat-I 解密只需密钥；Cat-II 被 mLDP 改过的数值默认不还原（要还原就必须存状态）。整条链路只依赖固定长度密钥，且支持任意顺序的“脱敏—反脱敏”。

实验

设置：GPT-4o、Gemini-1.5、OPUS-MT；NER 用 UniNER（在 AI4Privacy 的 10 类高风险实体上微调）、Llama-3 8B Instruct、Gemma-2 9B Instruct；四类任务 + 消融 + 与 Papillon 对比。

实验 数据与设置 指标 主要结果
机器翻译 WMT-14，英→德 / 英→法各 50 句，每句 1–2 个 PII BLEU 与未脱敏几乎持平。英→德 姓名：Gemini 0.334 → 0.341；GPT-4o 0.287 → 0.278；Papillon 仅 0.175。英→法 姓名：Gemini 0.423 → 0.408；GPT-4o 0.432 → 0.419；Papillon 0.290

结论：

  • 在“回答对敏感值不敏感”的不变式任务上，脱敏几乎不损性能；作者同时给出“模型对 prompt 满足 Lipschitz 连续性 / 敏感值参与符号计算”两类可解释的适用边界。
  • 表 5 横向对比显示：Prεεmpt 是唯一同时满足“无状态、形式化隐私、高可用、资源高效”四项的框架。
  • 局限：只覆盖单 token 级敏感信息；mLDP 数值不可逆（影响需精确回填的场景）；效果强依赖 NER；对上下文语义敏感、长尾事件仍可能失效——作者明确提醒不要把它当成“万能安全幻觉”。
