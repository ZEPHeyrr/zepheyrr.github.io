【论文阅读】【USENIX 26'】Sok： AI 系统的攻防全景回顾

论文信息

  • 标题：SoK: Attack and Defense Landscape of Agentic AI Systems

  • 链接

解决问题

对象：AI agent 是“LLM + 传统软件组件”的混合系统——LLM 做规划与决策，配记忆、工具、外部环境、用户界面与工作流。

与传统系统/单机 LLM 的本质区别：传统软件行为由源码里的程序逻辑预先确定，agent 行为由 LLM 动态生成；传统系统工作流预先编排，agent 工作流运行时生成。因此 agent 的“柔性”既是能力来源，也是风险来源——同一份柔性在不同维度上放大不同的攻击面。

现实动机：论文开篇即列举真实事件——提示注入被用来访问私有 GitHub 仓库、恶意文档附件与邮件转发导致数据外泄、服务器暴露用户聊天记录与凭证。这些事件说明 agent 的自动化能力让传统“单点”漏洞迅速升级为跨组件、跨系统的连锁事故。

研究空白：现有 LLM 安全综述停留在模型层（越狱、幻觉、后门），忽略 agent 因环境访问而扩大的攻击面与下游后果；已有 agent 研究多聚焦单一攻击向量、单一 agent 类型或单一组件（RAG 安全、工具安全）；设计导向的工作只给高层原则，没有把攻击与防御系统化；最接近的两篇综述虽考虑跨组件交互，但防御分类基本局限在“基于模型”的手段。

作者因此主张：agent 安全不能靠给单个组件打补丁，必须从系统层面做纵深防御。

SoK：分析框架和文献回顾

agent 的结构剖面——LLM 与 agent 工作流共同构成决策内核，向下连接内部 RAG 与记忆（会话轨迹、长期存储），向外经工具/系统与凭证触达计算机、Web、领域专用环境和第三方服务，向上经用户界面与用户交互，多智能体系统则是多个这样的内核并联

把 6 类攻击向量（紫色）与 7 类风险（红色）直接画在同一张数据流图上，一眼能看出“注入从哪个接口进来、最终在哪个组件爆掉”

图 3把 7 个设计维度与风险类别连成映射，并画出风险之间的级联箭头——接口风险如何喂养模型风险、模型风险又如何放大后果风险

按控制流阶段铺开防御手段，标出每种防御作用在输入、规划、工具调用、输出还是环境侧

七个分析维度

柔性单调地放大风险——接更多外部数据 → 间接注入入口变多；加持久记忆 → 记忆投毒有了靶子；接第三方工具 → 供应链风险；工作流交给 LLM → 推理被劫持的机会变多；动作从“说”到“做” → 信息泄露升级为环境破坏

维度 最低柔性 中等 最高柔性
输入信任 Input Trust 不接外部数据 预定义外部数据 任意外部数据
访问敏感性 Access Sensitivity 无敏感数据 预定义敏感数据 任意敏感数据
工作流 Workflow 简单聊天机器人 开发者固定编排 LLM 动态编排
动作 Action 只生成回答 回答 + 检索 回答 + 检索 + 执行
记忆 Memory 无记忆 会话内临时记忆 跨会话持久记忆
工具 Tool 无工具 已知可信工具 任意/动态发现工具
用户界面 UI 纯文本 Web 图片预览 可交互 Web 元素

攻击面

对手：外部对手（只能污染 agent 会检索的网页/文档）、用户级对手（直接投喂恶意输入）、内部对手（开发者或组件供应商，最难防）。

攻击向量：V1 间接提示注入、V2 恶意数据注入、V3 工具投毒、V4 直接提示注入、V5 模型投毒、V6 记忆投毒。

风险类别：

  • R1 异构不可信接口：接口多、信任级别杂，攻击入口远多于单机 LLM；
  • R2 错误指令遵循：模型听了攻击者的话，而不是用户/开发者的话；
  • R3 无约束/不安全数据流：传统系统靠类型系统、访问控制约束数据传播，agent 里数据可从任意输入自由流向任意输出（包括下一次工具调用）；
  • R4 幻觉与模型错误：在 agent 里幻觉会“落地”——例如攻击者抢注 LLM 常幻觉出的包名，把模型缺陷变成供应链攻击；
  • R5 私有数据泄露：对话、持久记忆、工具凭证、环境资源之间的交互被利用（外带 URL 自动抓取、SSRF/XSS/路径穿越/SQL 注入等）；
  • R6 非预期/未授权动作与数据损坏：不可逆状态变更（乱下单、任意代码执行）与直接篡改存储；
  • R7 资源耗尽与拒绝服务：刷 API、死循环、撑爆内存；
  • 另有两类“其他风险”：系统提示/工具描述/配置等知识产权被窃取；基于工具执行时序、API 调用序列、流量模式的侧信道（作者称尚无人系统研究）。

系统级放大：R1 扩大入口 → 触发 R2/R3/R4 → 再放大为 R5/R6/R7，形成级联。这是“组件级防御不够”的直接论据。

防御框架

大类 子类 代表工作/思路 主要覆盖风险
运行时防护 输入护栏、输出护栏、信息流控制与污点追踪、监控、人在回路 NeMo Guardrails、Constitutional Classifiers、llama-firewall、PromptShield；Progent/Conseca/Agrail、GuardAgent/ShieldAgent；CodeShield/HeimdallM；URL/网络白名单 R1、R2、R4、R5、R6
设计即安全 权限分离、形式化验证 AirGap、f-secure LLM、CaMel、FIDES 的“规划器-解析器”分离；PFI 的沙箱切换；IsolateGPT 的应用级隔离 R2、R3
身份与访问管理 身份管理、访问控制、凭证管理 SSO/OIDC、去中心化身份、任务级短期身份；RBAC/ABAC 式策略；凭证不暴露给 LLM R5–R7
组件加固 模型加固、工具加固 SecAlign/StruQ 的指令层级微调；ETDI 的签名工具定义、MCP 代理审计、MCP Safety Audit R1、R2、R4

三条设计原则：纵深防御（输入→输出→信息流→监控→访问控制多层互补）、最小权限（权限分离、工具按需授权）、完全中介（每次敏感资源访问都被检查）
