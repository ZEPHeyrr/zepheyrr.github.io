取证软件

FTK Imager

这个题目下载解压后会得到两个e01、e02后缀的文件，属于EWF（EnCase Expert Witness Format）取证文件。为了查看内中的数据，我们依托FTK Imager+VMware将其仿真起来，以下是操作步骤。

Step1挂载模拟

Step1.1挂载镜像

File->Image Mounting

弹出的页面中选择e01文件，选择可写模式，点击mount挂载，并记下驱动器号。

挂载成功后，源文件所在路径会生成一个缓存文件。

Step1.2虚拟机仿真

新建虚拟机->自定义（高级）->下一步，虚拟机硬件默认设置->稍后安装操作系统

填写名称，位置可以自行选择

固件类型选UEFI

处理器、内存自行选择，有条件就多分一些。

网络链接选择NAT->IO选择 LSI Logic SAS->磁盘选择SATA类型->使用物理磁盘->设备选择FTK imager的驱动器号（比如我之前选择的是Physical Drive2）

然后就能进入系统了。

【如果挂载不了】Step2生成虚拟磁盘模拟

尝试了很多次，虚拟机运行不起来。所以我采用qemu生成了vmdk，再用vm打开虚拟机。

新建虚拟机时，在选择磁盘时选择现有即可。

但是我还是没把虚拟机跑起来，显示EFI引导存在问题，但是挂载后的引导系统不存在文件缺失。无奈放弃仿真运行虚拟机。

前序理论：

注册表

离线分析可以从系统注册表（hive）中提取信息。注册表路径通常是C:\Windows\System32\config\

文件 对应注册表根
SOFTWARE HKLM\SOFTWARE
SYSTEM HKLM\SYSTEM
SAM HKLM\SAM（用户密码哈希）
SECURITY HKLM\SECURITY
DEFAULT 默认用户配置

依赖的注册表分析工具：Registry Explorer

卷影副本

  • 全称 Volume Shadow Copy Service（VSS），中文叫“卷影副本”。
  • 系统定期（或装软件/打补丁前）给整个卷拍“快照”，文件被修改/删除时，旧内容被搬到 System Volume Information 里的差异区，快照仍然指向旧数据。
  • 所以：如果有人在系统里执行过 slmgr /ipk 换密钥、或把密钥值删了，当前 hive 里是新值/空值，旧密钥只在卷影里。这就是题目提示“卷影”的原因。
  • 访问卷影不是去 System Volume Information 里翻文件，而是通过系统接口把快照映射成一个目录，路径形如：\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\

产品密钥

注册表：\Microsoft\Windows NT\CurrentVersion\SoftwareProtectionPlatform

系统版本号

注册表值\Microsoft\Windows NT\CurrentVersion有一些值得注意的字段：

值名 含义
ProductName 产品名
EditionID 版本代号
DisplayVersion 功能更新版本
ReleaseId 旧版叫法
CurrentBuild 当前 Build
CurrentBuildNumber 同上（另一个值）
UBR 补丁号（DWORD）
BuildLabEx 完整构建串
CurrentVersion 兼容值，固定 6.3
