WEB-691

题面：

堵死了常规注入，过滤了一堆关键词，包含括号、等号（=），查询失败时不报错，只剩下一种语义： ORDER BY + echo $row['username']

解析：

注入 username 位置，把猜测串塞进 UNION 的第 3 列（password 列），让 MySQL 帮我们比较：

代码块

  • 'or 1：把 admin 真实行并进结果集（否则只剩我们一行，无从比较）
  • union select 1,'0',<GUESS>：第 1 列给真值过 if($row['id'])，第 2 列是信标（会被 echo），第 3 列是猜测
  • order by 3, 2：先按密码升序，平局再按信标列

实际执行：

设已知前缀 P。谓词 pred(c) = (P+chr(c) <= flag) 在字节序下对 c 单调:

  c <  F[i]  -> 小于

  c == F[i]  -> 小于(真前缀) 或 相等(回收尾那一位)

  c >  F[i]  -> 大于

=> 满足 pred 的最大 c 就是 F[i], 每位 log2(95)≈7 次 cmp, 每次 cmp=2 个请求。猜测串本身就是注入内容, 也会被 filter 检查。flag 一般不含表里的词, 但为稳:

一旦命中过滤词, 改用 binary 0x<hex>, hex 只含 0-9a-f, 不可能命中任何一个词。

于是 echo 成了比较器：

关系 回显
猜测 < flag 信标 0
猜测 > flag admin
猜测 == flag 由第 2 列决定 → 升序 0 / desc admin

WEB-692

解析

  1. config.php 内容形如 <?php $option='...'; ?>，可直接访问 /config.php 并被 PHP 执行；
  2. 每次请求都会把 config.php 里匹配到的 $option='...'; 整段替换成 $option='<addslashes(option)>'; 再写回；
  3. 只要让写回的结果跳出单引号串，请求 /config.php 就是任意代码执行。

preg_replace 替换串的转义把 addslashes 抵消

addslashes 本身是可靠的（' → \'）。但替换串 "\$option='$str';" 还要经过 preg_replace 的替换串解析，而它会把成对的 \\ 折叠成单个 \。

设输入在引号前放 k 个反斜杠：

k addslashes 后引号前 preg_replace 处理后的文件里 结果
0 \' \' 引号被转义，安全
1 \\\'(3个) \\' 先转义反斜杠 → 引号裸奔 → 闭合字符串
2 \\\\\'(5个) \\\' 又安全

所以 k=1 就能逃逸。替换串尾部还固定带一个 ';，用 // 注释掉即可。
